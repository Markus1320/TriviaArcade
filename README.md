# TriviaArcade

An open source trivia game in the style of classic arcade cabinets. Topics are geography
and history. Questions are generated by an LLM from a knowledge graph built from
[Wikidata](https://www.wikidata.org/), and a second LLM call judges your answers.
One wrong answer ends the run. Your streak is your score.

> Status: milestone 1 (skeleton). The page is a placeholder that shows backend health.

## Architecture

```
Browser (any device on the home network)
        |
      Caddy  :8080  (static frontend + reverse proxy, the only published port)
        |
       /api -> backend (FastAPI)
                 |          |            |
               Neo4j    PostgreSQL    Ollama API
```

| Service    | Purpose                                   | Ports                                         |
|------------|-------------------------------------------|-----------------------------------------------|
| `caddy`    | Serves the built frontend, proxies `/api` | `0.0.0.0:8080` (configurable via `CADDY_PORT`) |
| `backend`  | FastAPI app                               | internal only                                 |
| `neo4j`    | Knowledge graph (rebuildable)             | `127.0.0.1:7474`, `127.0.0.1:7687`            |
| `postgres` | Players, runs, leaderboard, logs          | internal only (see debugging below)           |

## Requirements

- [Docker Desktop](https://www.docker.com/products/docker-desktop/) with Docker Compose
- For local development outside Docker:
  - [uv](https://docs.astral.sh/uv/) (installs Python 3.12 for you)
  - Node.js 22 and npm

## Setup

1. Copy the environment template and fill in values:

   ```bash
   cp .env.example .env
   ```

   Set `POSTGRES_PASSWORD` and `NEO4J_PASSWORD` (Neo4j requires at least 8 characters).
   The Ollama values are not needed until the LLM milestone. Never commit `.env`.

2. Start the stack:

   ```bash
   docker compose up --build
   ```

3. Open <http://localhost:8080>. The page shows `OK` for backend, Postgres and Neo4j.
   The raw health endpoint is <http://localhost:8080/api/health>.

If port 8080 is already in use, set `CADDY_PORT` in `.env` (for example `CADDY_PORT=8081`).

## Playing from a phone on the home network

1. Find the host's local IP address. On Windows run `ipconfig` and use the IPv4 address
   of your Wi-Fi or Ethernet adapter (for example `192.168.178.x`). Ignore virtual
   adapters such as VirtualBox (`192.168.56.x`) or WSL/Hyper-V (`172.x.x.x`).
2. On the phone, connected to the same Wi-Fi, open `http://<host-ip>:8080`.
3. If it does not load, allow inbound TCP on the Caddy port in the Windows firewall
   (Docker Desktop usually does this for you), and make sure the network is set to
   "Private" in Windows.

Only Caddy is reachable from the network. Neo4j is bound to `127.0.0.1`, PostgreSQL is
not published at all.

## Development

### Backend

```bash
cd backend
uv sync
uv run ruff check .
uv run ruff format .
uv run mypy
uv run pytest
```

Add dependencies with `uv add <package>` (or `uv add --dev <package>`), never with plain `pip`.

### Frontend

```bash
cd frontend
npm install
npm run dev          # Vite dev server, proxies /api to the running stack on :8080
npm run lint
npm run format:check
npm run build        # type check and production build
```

### Debugging the databases

- Neo4j Browser: <http://localhost:7474> (log in with `NEO4J_USER` / `NEO4J_PASSWORD`).
- PostgreSQL on `127.0.0.1` (set `POSTGRES_DEBUG_PORT` if 5432 is already in use):

  ```bash
  docker compose -f docker-compose.yml -f compose.debug.yml up -d
  ```

### CI

GitHub Actions runs linters, type checks and tests for backend and frontend and
validates the Compose files on every push.
